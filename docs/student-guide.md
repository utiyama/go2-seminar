# ゼミの進め方

[教材トップ](../README.md) ／ [教科書の読む範囲](../materials/textbook/README.md)

各回は、教科書の担当者による発表、質疑、実習の順に進めます。発表は25〜30分、質疑は10〜15分、実習は45分ほどを予定しています。

## 予習

各回のREADMEにある範囲を、配布されたPDFで読んでおいてください。気になった用語や疑問点は、授業で取り上げます。必要に応じて、自分用にメモしておくと便利です。数式は、変数の意味や単位、どの座標系で表しているかを確認しながら読んでください。

全文版と抜粋版のページ対応は[教科書の案内](../materials/textbook/README.md)にあります。

## 発表

担当者は、その章で扱う問題と解き方を説明してください。主要な式やアルゴリズムは、図や小さな数値例があると伝わりやすくなります。どんな前提で成り立つ方法なのか、使えない場面はあるのかも取り上げてください。

最後に、今回の実習と教科書の内容がどうつながるかを説明します。担当と当日の時間配分は授業で確認してください。

## 実習

各回の `starter.py` をそのまま実行し、最初の結果を保存します。続いてREADMEの課題に沿ってコードを変更し、結果がどう変わるか調べてください。コード中の `TODO` は、変更する箇所の目印です。

コマンドは `README.md` があるフォルダから実行します。week01の場合は次のとおりです。

macOS:

```bash
bash scripts/run.sh exercises/week01/starter.py --viewer
```

Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run.ps1 exercises/week01/starter.py --viewer
```

week01はGo2の動きと軌跡を画面に表示します。動作が終わったらウィンドウを閉じ、`results/week01.png` で位置と向きの変化も確認してください。保存済みのCSVを再生する方法は[week01の説明](../exercises/week01/README.md#すでに保存したcsvを見る)にあります。

結果は `results/` に保存されます。同じプログラムをもう一度実行すると上書きされるので、比較に使うCSVや画像は先にコピーしてください。例えば、変更前を `results/week01-baseline.csv`、変更後を `results/week01-changed.csv` として残します。

実行前の予想と実際の結果を比べ、気づいたことや疑問点を授業中に話し合います。うまく動かなかった場合も、試したことをその場で相談してください。

## 記録について

毎回の提出物はありません。コード、結果ファイル、発表資料を提出したり、GitHubへpushしたりする必要はありません。発表担当者は、用意した資料を授業で使ってください。

`results/` の中身はGitには保存されないので、後で見返したい結果は手元に残しておいてください。

## 教材の更新

更新があった場合は授業で案内します。

ZIPを使っている人は、新しいZIPを別のフォルダに展開してください。自分で書いたコードやメモ、結果が入った古いフォルダは残しておきます。新しいフォルダではセットアップをやり直してください。`.venv` や `.cache` は編集せず、`.venv` は他のフォルダからコピーしません。

Gitを使っている人は、自分の変更と結果を保存してから更新してください。競合が起きて困った場合は、変更を消さずに教員へ相談してください。

## 自主研究に進むとき

センサのノイズ、地図作成、経路計画、自己位置推定など、実習で気になった題材を掘り下げてください。比較する条件と評価に使う数値を決め、同じ条件で実験を再現できるようにしておくと、結果を考察しやすくなります。

コードを拡張する際は[APIと設計](architecture.md)を参照してください。歩行制御器や完成済みのSLAMは、この教材には含まれていません。
