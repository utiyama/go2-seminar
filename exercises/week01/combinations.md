# 動きを組み合わせる

[week01](README.md)の基本操作が終わったら、動作の順序や繰り返しを変えて経路を作ります。まず1〜3に取り組み、余裕があれば4・5も試してください。

## まず動かしてみる

教材の `README.md` があるフォルダから実行します。

macOS:

```bash
bash scripts/run.sh exercises/week01/sequence.py --viewer
```

Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run.ps1 exercises/week01/sequence.py --viewer
```

前進、左に90度旋回、短い前進の順に動きます。動作が切り替わる時刻と名前がターミナルにも表示されます。最後に2秒間停止し、その後はウィンドウを閉じるまで画面を残します。

最初の例の終点は、world座標で約 `(x, y) = (0.4, 0.2)` m、向きは90度です。実行するたびに、原点・向き0度から始まります。

編集するときは `sequence.py` を同じフォルダに `sequence_my.py` という名前でコピーしてください。以後はそのコピーを編集し、実行コマンドのファイル名も `sequence_my.py` に変えます。教材の更新と自分の変更が重なりにくくなります。

## 動作の書き方

編集するのは、ファイルの上の方にある `ACTIONS` です。リストの上から順に実行します。

```python
ACTIONS = [
    Action("前進", seconds=2.0, vx=0.2),
    Action("左に90度旋回", seconds=2.0, yaw_rate=math.pi / 4),
    Action("短く前進", seconds=1.0, vx=0.2),
]
```

| 指定 | 意味 |
|---|---|
| 最初の文字列 | 自分で付ける動作の名前。動作を決めるのは後ろの数値です |
| `seconds` | その動作を続ける時間。0.02秒の正の整数倍 |
| `vx` | ロボットから見た前方の速度。負なら後退。単位m/s |
| `vy` | ロボットから見た左方向の速度。負なら右へ移動。単位m/s |
| `yaw_rate` | 左旋回の角速度。負なら右旋回。単位rad/s |

指定しなかった速度は0です。例えば `Action("待つ", seconds=0.5)` と書くと0.5秒間停止します。前の動作の速度は引き継ぎませんが、位置と向きは引き継ぎます。途中で原点に戻したり、向きを直接書き換えたりせず、速度の指令を組み合わせてください。

直進の距離は「速度×時間」、その場で旋回する角度は「角速度×時間」です。`math.pi / 4` rad/sで2秒旋回すると90度になります。速度の上限は、並進が0.5 m/s、旋回が1.5 rad/sです。90度を1秒で回ると旋回速度の上限を超えるので、この例では2秒にしています。

## 1. 同じ動作でも、順序が変わるとどうなるか

最初の例から3つ目の動作を外し、次の2通りを比べます。

- A：前進2秒 → 左に90度旋回
- B：左に90度旋回 → 前進2秒

実行前に、それぞれの終点と向きを紙などに描いて予想してください。実行したら、画面の軌跡と最後に表示される `x`・`y`・`yaw` を比べます。

使った動作も、それぞれの動作にかけた時間も同じです。それでも終点が違うのはなぜでしょうか。「前進」がどちら向きの移動なのかを、ロボットの向きと一緒に説明してみてください。

## 2. 正方形を描き、出発時の状態に戻る

一辺0.4 mの正方形を作ります。まず「一辺を進む→左に90度旋回する」という2つの動作を `ACTIONS` に書き、コマンドの末尾に `--repeat 4 --target 0 0 0` を付けてください。

`--repeat` は動作列全体を繰り返します。繰り返すたびに位置や向きをリセットするわけではありません。

原点に戻れたら、次の変更を試してください。

1. 4辺を進み終わったあと、最後の旋回を省く。位置と向きのどちらが変わるか。
2. 時計回りの正方形にする。どの値の符号を変えればよいか。
3. 一辺0.4 m、もう一辺0.2 mの長方形にする。同じ2動作の繰り返しで作れるか。

途中だけ動作を変えたい場合は、`--repeat` を1に戻し、動作をリストに書き並べます。Pythonの `for` 文でリストを作っても構いません。

最終位置だけでなく、最終的な向きと途中の軌跡も確認してください。向きの0度と360度は同じです。画面を閉じた後のグラフでは、回転の経過を連続した角度で確認できます。

## 3. 帰り道の動作列を作る

最初の例の3動作に戻します。これを行きの経路として、その後に帰りの動作を追加してください。`--repeat` は1にします。

目標は、**通った道を逆にたどり、位置も向きも出発時の状態に戻すこと**です。`--target 0 0 0` を付けると、目標との差を最後に表示できます。

次の方法をそれぞれ試し、どれで戻れるか比べてください。

- 動作の順序だけを逆にする。
- 順序はそのままに、すべての速度の符号を反転する。
- 順序を逆にし、すべての速度の符号も反転する。

ここでは各動作の時間は正のままにします。帰り道の最初の動作を考えるときは、行きの最後にロボットがどちらを向いているかを確認してください。

できたら、行きの経路に横移動や別の旋回を追加しても、同じ方法で帰れるか試します。帰り道を手で書く代わりに、行きのリストからPythonで作る方法も考えてみてください。逆順の処理には `reversed()` が使えます。

## 4. 同じ終点に、違う向きで進む

最初の例と同じ `(0.4, 0.2)` mまで、向きを変えずに前進と横移動だけで移動してください。到着後に90度旋回すれば、終点の位置と向きも最初の例とそろえられます。

2つの方法で、平面上の軌跡と途中のロボットの向きを比べてください。同じ軌跡を通っていても、ロボットの状態は同じでしょうか。

さらに、`vx` と `yaw_rate` を1つの `Action` に同時に指定してみます。「前進してから旋回する」場合と「前進しながら旋回する」場合で、何が変わるでしょうか。

## 5. 小さな旋回のずれは、繰り返すとどうなるか

正方形の動作に戻し、各角の旋回を90度から89度に変えます。2秒で89度回る角速度は `math.radians(89) / 2` です。各辺の距離は変えません。

4回繰り返したときと、8回繰り返したときで、位置と向きがどれだけずれるか調べてください。`--target 0 0 0` の表示と、保存された軌跡の図を使って比べます。

向きのずれは足し算で求められますが、位置のずれも同じように求められるでしょうか。次の辺をどちら向きに進むかに注目してください。これは意図的に指令をずらした実験で、センサのノイズや床での滑りを加えたものではありません。

## 結果の比較

既定では `results/week01-sequence.csv` と `results/week01-sequence.png` に保存します。CSVは動作終了時、画像はウィンドウを閉じた後に作られます。同じ名前で実行すると上書きされるので、比較するときはコマンドの末尾に、例えば `--output results/square-89` のように保存名を指定してください。拡張子は付けません。

`--target X Y YAW_DEG` は、目標に対する最終位置の距離と、最終的な向きの差を表示するための指定です。この指定自体がロボットを目標へ動かすわけではありません。x・yはworld座標のm、向きはこの指定に限って度で与えます。例えば、最初の例なら `--target 0.4 0.2 90` です。

保存済みのCSVは、基本実習と同じ再生プログラムで見られます。例えばMacでは次のように実行します。

```bash
bash scripts/run.sh examples/06_replay.py results/square-89.csv --viewer
```

画面を使わずに結果だけ調べる場合は、実行コマンドの `--viewer` を `--headless` に変えます。途中でウィンドウを閉じた場合は、そこまでの結果を保存します。

この実習では胴体の平面移動を計算します。脚の歩行や接触は扱いません。動作の組み合わせによって、位置と向きがどう変わるかを調べてください。
